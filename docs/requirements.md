# 要件と受け入れ条件

## 利用者と目的

参加者が興味のあるイベントを探して予約し、主催者がイベントを公開・管理できること。一般ユーザー向けの一連の操作を、画面・API・DBを通して実装する。

## MVP

| ID | 要件 | 受け入れ条件 |
|---|---|---|
| R01 | 登録とログイン | パスワードを平文保存せず、CSRF保護付きでセッションを作成できる |
| R02 | 検索 | キーワード・カテゴリー・場所・空席で絞れ、ページを移動できる |
| R03 | 予約 | 公開中・受付期間内・空席ありのイベントに1席予約できる |
| R04 | 同時予約 | 残り1席への6件同時要求で成功は1件だけになる |
| R05 | 重複防止 | 同じユーザーの同時要求で予約人数が二重に増えない |
| R06 | キャンセル | 自分の予約だけを取り消し、同時要求・再送で空席を二重に戻さない |
| R07 | 主催 | 主催者として登録したユーザーが、自分のイベントを作成・編集できる |
| R08 | 定員変更 | 予約人数より小さい定員に変更できない |
| R09 | 所有者の制限 | 他人の予約、他の主催者のイベントや予約者一覧にアクセスできない |
| R10 | 異常時の画面 | 通信失敗・入力エラー・満席・受付終了・検索結果なしを案内する |
| R11 | レスポンシブ | デスクトップと幅390pxの画面で横にはみ出さない |

## 業務ルール

- 予約はアカウントごと・イベントごとに1席。キャンセルした予約は受付期間内なら再度有効にできる。
- 予約・キャンセルは現在時刻が期限未満の場合に許可する。期限と同時刻は締切後。
- 予約締切とキャンセル期限は開始日時以前、終了日時は開始日時より後。
- 保存はUTC、画面の表示は日本時間。主催者の日時入力は端末のローカル時刻として解釈し、ISO 8601へ変換する。
- 定員は1〜10000人。予約人数より小さくはできない。
- 予約のあるイベントを下書きへ戻せない。開催中止にしても予約履歴は保持する。
- 開催中止のイベントでは通常の期限後でも参加者が予約をキャンセルできる。
- イベント・予約をAPIから物理削除しない。
- 公開一覧は未終了の公開イベント。開催中止は一覧に出さず、詳細と自分の予約一覧で確認できる。
- 下書きは主催者だけが閲覧できる。主催者アカウントは他の主催者のイベントを管理できない。

## 今回含めないもの

決済、複数席予約、招待制、キャンセル待ち、座席指定、通知メール、本人確認、メール確認、パスワード再設定、開催履歴を含む全文検索。将来の追加機能と現在の実装を区別する。
